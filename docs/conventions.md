# Project Conventions

This document defines the standards and guidelines used throughout the Enterprise Infrastructure Lab.

The purpose is to keep the project organized, consistent, and maintainable as the infrastructure evolves.

# Documentation Standards

Every laboratory should follow the same documentation structure:

- Context
- Objectives
- Architecture
- Implementation
- Validation
- Evidence
- Troubleshooting
- Lessons learned
- Next steps

# Repository Organization

The repository should only contain completed or actively developed content.

Avoid creating empty structures without a real purpose.

New folders should be created when they are required by the project evolution.

# Naming Conventions

Naming standards will be defined before infrastructure deployment.

Examples:

- Virtual machines
- Servers
- Networks
- Users
- Groups
- Services

# Git Commit Standards

Commits should follow this format:

\<type> : \<description"

Allowed types:

- add: Add new content or functionality.
- update: Improve existing content.
- fix: Correct errors or issues.
- remove: Delete unnecessary content.

Description has to be written in imperative form

Prefer:

    add: Create project roadmap

Instead of:

    add: Created project roadmap>
